## 1. Как матрица хранится в памяти

Матрица — таблица. `i` обозначает номер строки, `j` — номер столбца.
В C++ индексы начинаются с нуля. Для матрицы 2 x 3:

```text
       j=0 j=1 j=2
i=0     1   2   3
i=1     4   5   6

В памяти: 1 2 3 4 5 6
Индексы: 0 1 2 3 4 5
```

Если столбцов `cols`, индекс элемента — `i * cols + j`.
Например, элемент строки 1, столбца 2 находится по индексу `1*3+2 = 5`.
В нашем квадратном случае `cols = N`, поэтому пишем `A[i * N + j]`.

```cpp
size_t N = 3;
auto A = std::make_unique<double[]>(N * N);
for (size_t i = 0; i < N; ++i)
{
    for (size_t j = 0; j < N; ++j)
    {
        A[i * N + j] = i + j;
    }
}
```

Это один непрерывный массив. Здесь `A` не является `double**` и не поддерживает
запись `A[i][j]`. `A.get()` передаёт в функцию указатель на начало массива,
как `data.get()` в первых практиках.

Матрица 2048 x 2048 содержит 4194304 элемента `double` и занимает 32 МиБ.
В режиме 1 вместе с входами и тремя результатами используется около 160 МиБ.

## 2. Четыре разных задания

Пусть:

```text
A = 1 2     B = 5 6     x = 10
    3 4         7 8         20
```

**Сумма элементов A:** `1+2+3+4 = 10`. Результат — одно число.
Это почти первая практика: два цикла, общая сумма и `reduction(+:s)`.

**Сложение A+B:** складываем соответствующие элементы.

```text
C = 6  8
   10 12
```

Формула: `C[i,j] = A[i,j] + B[i,j]`. Размеры A и B должны совпадать.
Два цикла, работа порядка N^2.

**Матрица на вектор A*x:** каждую строку матрицы умножаем поэлементно
на вектор и складываем произведения.

```text
y[0] = 1*10 + 2*20 = 50
y[1] = 3*10 + 4*20 = 110
```

Формула: `y[i] = сумма A[i,j]*x[j] по всем j`.
Матрица размера rows x cols умножается на вектор длины cols;
результат имеет длину rows. Для квадратной матрицы работа порядка N^2.

**Матрица на матрицу A*B:** строку A умножаем на столбец B.

```text
C[0,0] = 1*5 + 2*7 = 19
C[0,1] = 1*6 + 2*8 = 22
C[1,0] = 3*5 + 4*7 = 43
C[1,1] = 3*6 + 4*8 = 50

C = 19 22
    43 50
```

Формула: `C[i,j] = сумма A[i,k]*B[k,j] по всем k`.
Размеры: `(rows x inner) * (inner x cols) = (rows x cols)`.
В квадратном случае получаются три цикла — i, j, k — и работа порядка N^3.
Если удвоить N, число элементов возрастёт в 4 раза, а работа обычного
умножения матриц — примерно в 8 раз. Поэлементное умножение `A[i,j]*B[i,j]`
является другой операцией.

## 3. Что именно распараллеливаем

Для A*x удобно разделить строки: одна итерация внешнего цикла вычисляет
один результат `y[i]`. Важный фрагмент из рабочего файла:

```cpp
#pragma omp parallel for schedule(static)
for (size_t i = 0; i < N; ++i)
{
    double s = 0.0;
    for (size_t j = 0; j < N; ++j)
    {
        s += A[i * N + j] * x[j];
    }
    y[i] = s;
}
```

`parallel for` распределяет итерации внешнего цикла между потоками.
`schedule(static)` задаёт предварительное распределение; оно подходит,
когда стоимость обработки строк примерно одинакова.

`s` объявлена внутри тела цикла и является локальной для выполняющего
его потока. A и x только читаются. Разные строки записывают разные `y[i]`.
Поэтому здесь нет одной общей суммы и не требуется `reduction`.
В сумме всех элементов матрицы одна общая переменная есть — там `reduction` нужен.

При A*B аналогично делим строки C. Выходные массивы в примере выделяются
отдельно от входных: не передавай x как y или A/B как C при умножении.

## 4. Продолжение темы локальности

В выбранном хранении соседние элементы строки лежат рядом:

```cpp
// Сначала i, затем j: читаем подряд.
for (size_t i = 0; i < N; ++i)
    for (size_t j = 0; j < N; ++j)
        /* A[i * N + j] */;

// Сначала j, затем i: между чтениями шаг N элементов.
for (size_t j = 0; j < N; ++j)
    for (size_t i = 0; i < N; ++i)
        /* A[i * N + j] */;
```

Обычно чтение по строкам лучше использует кеш для достаточно больших матриц
в таком хранении. В `task = 2` функция `matrix_vector_columns` считает тот же
результат последовательно, но обходит A по столбцам. Сравни её время с
`matrix_vector`. Это сравнение порядка чтения, оба варианта последовательные.

У обычного умножения i-j-k матрица B читается по столбцу: `B[k*N+j]`.
В `matrix_multiply_local` циклы переставлены в порядок i-k-j, и внутренний
цикл читает B по строке. Сравни её с `matrix_multiply_parallel`: обе функции
параллельные, но с разным порядком доступа.

Слово `local` в имени функции не обещает ускорение на любом размере и CPU:
скорость нужно измерить.

## 5. Ошибки, которые легко сделать на паре

- **Перепутать количество элементов и размер стороны:** матрице N x N нужно N*N элементов.
- **Забыть умножить номер строки на число столбцов:** `A[i+j]` не заменяет `A[i*N+j]`.
- **Объявить общую s перед параллельным циклом A*x:** возникнет одновременная запись
  в одну переменную. Ставь `double s = 0.0;` внутри цикла по строкам.
- **Обнулить s только один раз:** у каждого элемента C при i-j-k должна быть своя сумма.
- **Использовать += без обнуления:** результат будет зависеть от предыдущего содержимого.
  В i-k-j обнуляем строку C при каждом вызове.
- **Поставить parallel for над столбцами `matrix_vector_columns`:** разные j будут
  одновременно прибавлять к одним и тем же y[i]. Этот вариант специально последовательный.
- **Распараллелить k при общем C[i,j] без объединения сумм:** та же гонка данных.
- **Сравнить только суммы результирующих матриц:** разные ошибочные матрицы могут
  иметь одинаковую сумму. Здесь сравниваем все элементы через `max_error`.
- **Ожидать обязательную ненулевую ошибку:** текущие входы — небольшие целые числа,
  поэтому нулевая ошибка нормальна. На дробных данных возможны отличия округления.

## 6. Как читать вывод и сравнивать время

`Max error` — максимум `abs(serial[i] - parallel[i])` по всем результатам.
Это абсолютная ошибка относительно последовательной реализации, а не
относительная ошибка из первых практик и не доказательство правильности обеих
реализаций. Для проверки формул есть маленький пример выше и отдельные проверки кода.
`Result [0]` показывает только первый элемент для ориентира; проверка охватывает все.

Время — среднее на один вызов по пяти повторам; создание массивов, заполнение,
сравнение и печать в измерение не включены. Запуск потоков входит во время
параллельного вызова. `Speedup = serial_ms / parallel_ms`.
Больше 1 означает ускорение, меньше 1 — замедление.
Таймер имеет конечную точность: если время округляется к нулю, увеличь repeats или N.

Для учебной отладки задача использует `-O0`. Для оценки скорости оптимизированной
программы собери тот же исходник с `-O2`, предварительно запусти обе сравниваемые
функции для прогрева, затем измеряй без отладчика и повтори эксперимент.
Даже пять повторов подряд не устраняют полностью влияние нагрузки, частоты CPU,
порядка запусков и кеша. Точки останова внутри замера включают паузу в измеренное время.
